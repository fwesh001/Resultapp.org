fix(audit): capture cur.description before the COUNT query

The COUNT ran after the rows were fetched but before _row_to_dict, and
_row_to_dict names columns from cursor.description. Executing the COUNT
replaces description with a single 'count' column, so every audit row came
back mapped as {"count": 4, "created_at": ""} — the read endpoint returned
one nonsense entry with no actor, action or details.

Fetching the rows first is not sufficient; the description has to be
captured before the second execute. Found by driving the route live, not
by reading the code — both SQL statements are correct in isolation, which
is exactly why reading them was not enough.
